# 软件设计师考试填空题训练

## Overview

为软件设计师考试生成填空题，用户在文件中作答，AI 批改并对错题加详细注释。

## Workflow

```
用户请求出题 → 写入文件 → 用户填空 → 用户说"答题完毕" → 批改 → 加注释 → 等待下一题
```

## Step 1: 出题

**确定题型：**
- 用户说 `question.java` 或提到设计模式 → Java 设计模式题
- 用户说 `question.c` 或提到算法 → C 算法题
- 用户未指定 → 交替出题，兼顾两类

**写入文件：**
- Java 题 → `question.java`
- C 算法题 → `question.c`

**出题规范：**
- 空位用 `/* (1) */` 标记，编号连续
- 部分空位填单个词（如 `implements`、`extends`）
- 部分空位填完整语句（如 `high = mid - 1;`、`arr[i] = arr[j];`）
- 只在代码顶部写说明注释（变量说明、函数说明），不要在代码每一步加注释
- 必须有客户端调用/测试代码，展示预期输出
- 不要给参考答案
- 代码风格用完整大括号，不要省略（if/else/while/for 都要带 {}）
- 接口方法名如果是填空，题目中其他调用处必须暗示该方法名，避免命名歧义；批改时只要前后调用一致就不算错

**常考设计模式：**
- 策略模式 Strategy
- 观察者模式 Observer
- 工厂方法模式 Factory Method
- 抽象工厂模式 Abstract Factory
- 装饰器模式 Decorator
- 适配器模式 Adapter
- 模板方法模式 Template Method
- 建造者模式 Builder
- 单例模式 Singleton
- 代理模式 Proxy
- 命令模式 Command
- 状态模式 State

**常考算法：**
- 排序：冒泡、快排（挖坑填数）、归并、插入、选择
- 查找：二分查找
- 链表：插入、删除、反转、查找
- 动态规划：0-1背包、最长公共子序列、最长递增子序列
- 回溯：N皇后、全排列
- 图：DFS、BFS、最短路径

## Step 2: 等待作答

出题后只说一句话，告知空数和注意事项，等用户说"答题完毕"。

## Step 3: 批改

**读取用户填好的文件，逐空判定：**

1. 生成判分表格，包含：空号、用户答案、正确答案、✓/✗
2. 对错误答案简要解释原因（1-2句话）
3. 给出总分（如 5/7）

**然后修改文件，处理错题：**

对每个填错的位置：
1. 将错误代码替换为正确代码
2. 在正确代码旁加注释 `// 错误写法：xxx`，保留用户原始错误答案
3. 给**整个代码**加上详细的中文注释，每一步都解释清楚目的和原理

注释要求：
- 每个函数说明作用
- 每个关键步骤说明原理（如状态转移方程、循环边界、指针操作）
- 对比正确 vs 错误写法的区别
- 目的：让用户通过阅读完整代码就能理解和记忆

## Step 4: 等待用户查看解析

批改完毕后**不出题**，等待用户说"出题"或"继续"时再出下一题。
给用户留时间查看解析和注释。如果用户指定了薄弱方向，优先出该方向的题。

## Common Mistakes

| 错误 | 说明 |
|------|------|
| 出题给了答案 | 出题阶段绝不给参考答案 |
| 批改只说对错不解释 | 必须解释为什么错、正确写法是什么 |
| 只改错题不加注释 | 必须对整个代码加详细注释帮助记忆 |
| 忘记保留错误答案 | 修改时必须用注释保留用户原始错误 |
| IDE报错就修 | IDE报错可能是空位导致的，出题阶段不处理 |
